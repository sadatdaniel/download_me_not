Privacy policy

getaload · last updated 14 October 2026

Who runs what

getaload is software that people install on a server they control. There is no getaload service: the developers do not run servers for users and receive no data from installations. Whoever installs a getaload server is responsible for it and for the people they give accounts to.

What a getaload server stores

On its own disk only: the downloads its users ask for, each user's name and a hash of their PIN, per-device sign-in tokens (stored hashed), each user's settings and watch progress, and, if a user adds them, their cookies for sites that need a sign-in. Secrets are stored encrypted. Nothing is sent to the developers or to third parties, except the requests a user's own downloads need and the server's checks for new releases of itself and its helper tools on GitHub.

Google user data

If a user chooses to connect Google Drive, getaload asks Google only for the drive.file permission: access to the files that getaload itself creates in that user's Drive, not to anything else in it. getaload uses this solely to upload the files the user asks it to copy there. The resulting Google token is stored encrypted on that user's own server, for that user only, and is not shared with anyone. It is not used for advertising, not sold, and not used to train AI or machine learning models.

getaload's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Removing access

A user can disconnect Google Drive at any time in the app (Settings, Google Drive, Disconnect), which deletes the token from the server, or revoke access in their Google Account permissions. Removing a user from a server deletes their sign-ins, cookies and Google token.
